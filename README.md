# 교내 카페 사전 주문 서비스 · 화면·기능 통합 문서와 Live Demo

> 수업 중·이동 중에 미리 주문하고, 원하는 시간에 “픽업만” 하게 만든다.

교내 카페 사전 주문 서비스의 **화면 정의(와이어프레임 W1–W5) · 기능명세(F0–F7, OP) · IA · User Flow**와 **직접 조작할 수 있는 React 데모**를 한 사이트에서 보여줍니다. 팀원은 같은 화면 ID(W1–W5)와 기능 ID(F0–F7)를 기준으로 기획 의도와 구현 결과를 함께 확인할 수 있습니다.

## 메뉴

- **전체 흐름 보기**: 개요(Target · Problem · Insight · Solution), W1–W5 카드(정적 미리보기 · 목적 · 다음 이동 경로 · 문서 보기 / 시연하기), Figma User Flow와 IA 원문
- **문서 보기**: 화면 개요 → 화면 설명(주요 동작 · 상태·예외 · 원문 미기재) → 확대·축소 가능한 프레임과 번호별 구성 요소 → 기능명세 순서로 읽습니다. 프레임 번호를 누르면 같은 문서 안의 설명이 강조됩니다.
- **시연하기**: 문서와 독립된 실제 React UI입니다. 카페 선택 → 메뉴 → 옵션 바텀시트 → 주문서(픽업 시간 · 결제수단) → Mock 결제 → 주문 상태 · 준비 완료 알림까지 조작할 수 있습니다. 오른쪽 시연 패널에서 슬롯 마감과 결제 실패 예외를 재현할 수 있습니다.

모든 내용은 Figma 파일 「교내 카페 사전 주문 서비스 - 과제」에서 가져왔습니다.

| 섹션 | 사용한 곳 |
|---|---|
| 00 개요 | 전체 흐름 보기 상단 개요 |
| 01 기능 정의 (F0–F7, OP, 제외 기능) | 기능명세 카드 |
| 02 IA | 전체 흐름 보기 IA, 화면별 들어오는 곳 · 나가는 곳 |
| 03 User Flow | 전체 흐름 보기 User Flow, 화면 · 기능 예외 처리 |
| 04 Wireframe (W1–W5와 캡션) | 문서용 프레임, 번호별 구성 요소, 시연 UI |
| 05 재사용 컴포넌트 | `src/ui.tsx` 공용 컴포넌트 (Top Bar · Button · Chip · Menu Row · Cafe Card · Tab Bar) |
| 06 CHECK | 계산 규칙 (예상 대기시간, 슬롯 마감) |

- Notion 화면 정의서 · 기능명세 DB는 없어서 Figma 캡션과 기능 정의 표를 원문으로 사용했습니다.
- Figma Dev Mode 추출 코드는 받지 않았습니다. 프레임은 Figma 화면을 보고 React로 다시 그렸습니다 (`src/Wireframes.tsx`).
- 구성 요소 번호는 **Figma 원본의 연두색 번호(note 1–4)를 그대로** 사용합니다.
- 원문에 없는 항목(Actor · Trigger · 선행 조건 · QA 기준, 빈 상태, 최댓값 등)은 임의로 채우지 않고 「원문 미기재 · 확인 필요」로 표시합니다.
- 자세한 매핑은 [MAPPING.md](./MAPPING.md)에 있습니다.

## Mock 범위와 제한

- 실제 서버, 간편결제(PG), 푸시 알림과 연결하지 않은 **정적 데모**입니다. 결제는 실제로 처리되지 않습니다.
- 카페 · 대기 건수 · 예상 시간 · 커피 메뉴 · 슬롯 · 주문 A-24는 와이어프레임 표시값입니다. 논커피 · 티 메뉴는 데모용 Mock 값이고, 베이커리는 빈 상태로 둡니다 (`src/mockData.ts`).
- 기준 시각은 10:37로 고정했습니다.
- 주문 상태는 타이머(4초 → 6초) 또는 시연 패널 「다음 단계」로 진행합니다. 직원용 운영 화면(OP)을 대신하는 장치입니다.
- 샷 0–3, 수량 1–10은 데모용 임시 한도입니다 (원문 미기재).
- 새로고침하면 주소의 화면이 처음 Mock 상태로 다시 열립니다. 저장 유지 정책은 원문 미기재입니다.

## 미구현 항목

- F0 간편 로그인: 와이어프레임이 없어 로그인된 상태를 가정합니다.
- OP 운영 주문 접수 화면: 학생 앱 범위 밖입니다.
- 주문 내역 · 마이 탭: IA 노드만 있고 와이어프레임이 없어 최소 구성으로 표시합니다.
